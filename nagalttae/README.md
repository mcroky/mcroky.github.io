# 나갈때

약속이 10시이고 10분 일찍 도착하고 싶다면 도착 목표는 9시 50분입니다. 이동에 30분, 준비에 20분이 걸리면 9시 20분에 출발하고 9시에 준비를 시작하면 됩니다. 나갈때는 이 계산을 브라우저에서 해 주는 작은 웹앱입니다.

## 바로 사용하기

1. 이 폴더의 `index.html`을 브라우저로 엽니다.
2. **약속 날짜**를 눌러 오늘·내일 또는 원하는 날짜를 고릅니다. **시간 변경**으로 약속 시각을 바꾸고 **조정**에서 준비·이동·도착 여유 시간을 설정합니다. 각 소요 시간은 0분부터 240분까지 설정할 수 있습니다.
3. 첫 화면에서 출발 시각과 준비 시작 시각을 확인합니다. 전체 타임라인은 **상세 일정**을 열어 볼 수 있습니다. 전날에 준비하거나 출발해야 하면 해당 시각에 전날 표시가 붙습니다.
4. **알림 예약**을 열어 준비·출발 날짜와 시각을 확인한 뒤 예약합니다. 캘린더 파일, 시계로 옮기기, 티켓 이미지 저장, 일정 복사와 공유는 **더보기**에 모여 있습니다.
5. **일정 저장**을 누르면 약속 날짜와 시각, 준비·이동·도착 여유 시간이 이 기기의 브라우저에 저장됩니다. 상단의 **저장한 일정**에서 편집하거나 삭제할 수 있습니다.

한국어, 영어, 일본어, 중국어 간체를 지원합니다. 선택한 언어는 이 브라우저에 저장합니다. 마지막으로 완성한 약속 날짜·시각, 준비·이동·여유 시간은 현재 탭의 세션 저장소에 보관해 새로고침 후 복원합니다. 약속 이름은 내려받는 캘린더 파일에만 담습니다. 브라우저에서 저장을 차단한 경우에는 새로고침 전에 필요한 일정을 복사하거나 파일로 저장하세요.

## 주변 대중교통

**주변 교통**을 열고 위치를 허용하면 반경 3km 안에서 가까운 버스 정류장과 지하철역을 찾습니다. 역이나 정류장 이름으로도 검색할 수 있습니다. 도착 정보가 제공되는 곳은 남은 시간이 표시되고, 지하철 예정 시각은 **시간표**에서 확인할 수 있습니다.

지하철 위치와 시간표는 철도공단의 전국 자료를 사용합니다. 역별 자료 기준일은 시간표 아래에 표시됩니다. 원본을 갱신할 때는 `python verification/import-timetable.py <역사 XLSX> <운행정보 XLSX>`를 실행해 역 목록과 노선별 시간표를 다시 생성합니다. [역사 위치 원본](https://data.kric.go.kr/rips/M_01_01/detail.do?id=32) · [운행정보 원본](https://data.kric.go.kr/rips/M_01_01/detail.do?id=900)

하루를 24시간으로 보고 현지 시계에서 분을 거꾸로 뺍니다. 서머타임이 시작되거나 끝나는 구간, 서로 다른 시간대를 오가는 일정에는 별도로 시차를 반영해야 합니다.

## 웹앱을 홈 화면에 설치하기

[나갈때](https://mcroky.github.io/nagalttae/)를 열고 **앱 설치**를 누릅니다. 설치를 지원하는 브라우저에서는 확인창이 열립니다. 아이폰에서는 Safari의 공유 메뉴에서 **홈 화면에 추가**를 선택하고 **추가**를 누릅니다. **웹 앱으로 열기**가 보이면 켜 주세요.

홈 화면 아이콘으로 연 앱에서는 위쪽의 **새로고침**을 누르면 새 버전을 확인합니다. 인터넷에 연결되어 있으면 새 파일을 모두 받은 뒤 최신 버전이 표시됩니다. 현재 버전은 화면 상단 앱 이름 옆에 표시됩니다.

온라인에서 처음 연 뒤 필요한 파일이 저장되면 인터넷 연결이 끊겨도 약속 시간을 계산할 수 있습니다. 준비·출발 알림을 사용하려면 **캘린더에 담기**에서 내려받은 파일을 캘린더 앱으로 가져옵니다.

기본 시계 앱을 쓸 때는 시간표 아래 **준비 시각 복사** 또는 **출발 시각 복사**를 눌러 시각을 확인한 뒤 시계 앱에 입력합니다. 준비와 출발에 캘린더 알림을 받으려면 **준비·출발 알림 파일 받기**로 한 파일에 저장합니다.

아이폰에서는 시각을 복사할 때 시계 앱 열기를 시도합니다. **시계에 옮기기**에서 날짜와 시각을 함께 확인해 기본 시계 앱에도 직접 입력할 수 있습니다. 같은 일정으로 창을 다시 열면 입력한 항목의 체크가 유지됩니다.

## Android 앱에서 알람 사용하기

**[Android 미리보기 APK 1.3.1](../nagalttae-android-preview-1.3.1.apk)**을 휴대폰에 복사하거나 내려받은 뒤 파일을 열고 **설치** 또는 **업데이트**를 누릅니다. 처음 설치할 때 기기가 권한을 물으면 파일을 연 브라우저 또는 파일 앱에 **이 출처 허용**을 선택하고 설치 화면으로 돌아갑니다.

Android 8.0(API 26) 이상에서 사용할 수 있으며 대상 API는 36입니다. 앱에 포함한 플래너를 열기 때문에 일정 계산과 알람 설정은 오프라인에서도 사용할 수 있습니다. 직접 설치하는 디버그 미리보기의 앱 ID는 `com.rokystudio.nagalttae.preview`입니다.

1. 약속을 입력한 뒤 **알람 설정**을 누릅니다. 준비 시작과 출발 중 필요한 시각을 선택하세요. 둘 다 선택할 수 있습니다.
2. 권한 안내가 표시되면 앱 알림과 정확한 알람을 허용하고 앱으로 돌아옵니다. 이미 지난 시각이나 현지 시계 변경으로 건너뛰거나 반복되는 시각은 다른 시각으로 바꾸세요.
3. **선택한 알람 예약**을 누르고 **예약된 알람**에서 시각을 확인합니다. 한 번에 약속 한 건의 알람을 보관합니다. 새로 예약하면 이전 알람을 교체하며, **예약된 알람 취소**로 해제할 수 있습니다.

앱은 시스템에 알람을 예약합니다. 재부팅 후 잠금을 해제하면 저장된 시각 중 아직 지나지 않은 알람을 다시 예약하도록 구성했습니다. 클립보드 복사, 티켓 PNG와 캘린더 파일 저장은 Android 기능을 사용합니다.

### Android 앱 빌드

JDK 17과 Android SDK 36을 준비하고 SDK 위치를 `ANDROID_HOME` 또는 `local.properties`의 `sdk.dir`로 지정합니다. Windows에서 프로젝트 경로에 한글이 있으면 `index.html`과 `android/`가 함께 있는 프로젝트 전체를 `C:\work\nagalttae`처럼 영문 경로에 복사합니다. `android` 폴더에서 다음 명령을 실행합니다.

```powershell
.\gradlew.bat assembleDebug lintDebug
```

## 웹 배포

공개 주소는 [나갈때](https://mcroky.github.io/nagalttae/)입니다. 정적 파일은 `mcroky/mcroky.github.io`의 `main` 브랜치에 있는 `nagalttae/` 폴더에 배포합니다.

1. 상위 폴더의 `nagalttae-web.zip`을 풀고 파일 구조 그대로 게시 폴더에 올립니다. 빌드 명령은 필요하지 않습니다. 호스팅 주소가 바뀌면 `index.html`의 canonical 링크와 `og:image`, `twitter:image`, `og:url`에 새 절대 주소를 반영합니다.
2. 공개 주소를 휴대폰에서 열고 약속 시간을 바꿔 봅니다. **일정 복사**와 **X에 공유**로 같은 출발 시각이 전달되는지, X 작성 화면에 링크 미리보기가 뜨는지 확인합니다.
3. Roky Studio 홈페이지에 프로젝트 카드, 실제 공개 링크와 업데이트 소식을 추가하고 의견 폼의 프로젝트 선택지에 나갈때를 등록합니다.
4. 아래 X 초안을 확인하고 게시합니다.

웹은 모바일·데스크톱 브라우저에서 사용합니다. 일정 계산에 서버와 로그인이 필요하지 않습니다.

## 검증

웹 1.4.3과 Android 1.3.1은 Android 16 에뮬레이터의 Chrome에서 준비 시각 복사 버튼을 한 번 눌러 검사했습니다. 클립보드에 시각이 들어갔고 Google 시계의 알람 탭이 열렸습니다. 뒤로 가면 웹앱의 시각 안내가 다시 보였으며, 연결 앱이 없는 환경에서는 안내 화면으로 돌아갔습니다. iOS는 브라우저에서 열기 요청만 검사했습니다. Android 빌드·린트·v2 서명, 19개 Node 테스트, 웹 상태·캐시 모델 455개 상태와 변이 8개, Android 링크 입력 검사와 변이 4개가 통과했습니다. [시계 열기 검증](android/tests/verification/clock-bridge.md)

웹 1.4.2에서는 시간표 클릭 한 번에 선택한 시각 하나가 복사 요청으로 전달되는지 공개 웹앱에서 확인했습니다. 자정, 권한 거절 시 수동 선택, 복사 응답 순서가 바뀌는 경우와 오프라인 재실행을 검사했습니다. 복사 상태 모델 437개 상태와 변이 4개, 캐시 변이 4개, Node 회귀 테스트 19개를 검증했습니다. 시계 앱에서의 붙여넣기 지원은 기기마다 다릅니다. [복사 상태 검증](verification/clock-copy.md)

웹 1.4.1의 시계 앱 입력 안내는 브라우저에서 네 언어와 자정·윤일·연말 경계를 검사했습니다. 준비·출발 시각 각각의 복사와 수동 선택, 완료 표시의 유지와 초기화도 확인했습니다. 화면은 기존 준비·출발 계산 결과를 사용하며 시계 앱에 입력하는 일은 사용자가 합니다. 기존 Lean 분 계산 모델과 TLC 캐시 모델을 재실행했고, 캐시 변이 4개 감지와 Node 회귀 테스트 19개 통과를 확인했습니다. ### Android 미리보기 1.3.0

Android 16 에뮬레이터에 APK를 설치하고 시스템에 준비·출발 알람 두 건이 예약된 것을 확인했습니다. 홈으로 나가 화면을 끈 뒤 에뮬레이터 시간을 각각의 예정 시각까지 진행했을 때 두 알림이 모두 표시됐습니다. 에뮬레이터 재부팅 및 잠금 해제 후 앱을 열기 전에 미래 알람 두 건이 다시 예약되는 것을 확인했습니다. 앱에서 알람을 취소하자 취소 안내가 표시됐고 시스템의 예약 목록에서도 두 건 모두 사라졌습니다.

Gradle 디버그 빌드와 린트가 통과했고 생성한 APK의 v2 서명을 확인했습니다. Node 테스트 15개를 통과했고, 브라우저에서 모의 Android 브리지와 요청·응답을 주고받는 동작도 확인했습니다. 시스템 알람 모델에서 176개 상태를 탐색했고 의도적으로 삽입한 오류 4개를 모두 검출했습니다. 실제 Java의 권한·예약 조건은 162개 입력 조합으로 검사했습니다. [Android 알람 검증](verification/native-alarms.md)

최종 APK에서 Android의 뒤로가기로 알람 창을 닫고, 저장 위치 선택을 취소하거나 계속하는 흐름도 확인했습니다. 기기에 저장된 1200×900 PNG와 캘린더 파일을 읽어 확인했습니다.
