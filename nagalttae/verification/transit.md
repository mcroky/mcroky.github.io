# 버스 조회의 늦은 응답과 차량 선택

직전 버전의 기준은 소스 커밋 `50fb4b8`과 Pages 커밋 `5fe63f0`에 공통으로 들어 있는 `transit.js` Git blob `4d63600dd839af95cf87dcbe687de0afec38fd5b`이다. 업데이트에 앞서 기존 정류장 선택 모델을 다시 검사해 19,260개 상태, 도달 검사 9개, 변이 9개에서 이전 결과를 확인했다.

| 실제 코드 | 모델에 반영한 동작 |
| --- | --- |
| `mount`, `reset`, 위치 조회 및 직접 검색 | 첫 화면에서 GPS 요청을 한 번 시작한다. 사용자가 다른 검색이나 정류장 선택을 하면 앞선 GPS·목록 응답은 화면을 바꾸지 않는다. |
| `load`, `select`, 도착 정보 재조회 | 도착 응답과 오류를 받으면 요청 세대와 정류장 ID를 확인한다. 본문에 적힌 정류장도 요청과 일치해야 한다. 지도만 제공하는 정류장을 고르면 실시간 요청을 만들지 않고 이전 정류장의 도착 정보를 비운다. |
| `render`, `load`, `select`, 차량 선택 핸들러 | 화면을 비워도 선택한 차량 식별자를 보관한다. 선택한 차량이 사라지면 출발 예약을 비활성화한다. 사용자가 다른 차량을 고르거나 원래 차량이 다시 목록에 나타나면 해당 차량을 선택한다. 정류장을 새로 선택하면 첫 차량부터 표시한다. |

## 모델 검사

| 모델 | 검사 범위 | TLC 1.7.4 결과 |
| --- | --- | --- |
| `tla/TransitSelection.*` | 자동 위치 요청 이후 사용자 동작 3회·4회까지, 도착 정보를 조회하는 정류장 2개와 외부 링크만 제공하는 정류장 1개에서 GPS·목록·도착 응답의 순서를 검사 | 16,214개와 146,050개 상태, 도달 검사 13개 통과, 변이 12개 검출 |
| `tla/TransitRide.*` | 차량 식별자 2개 및 3개, 익명 차량 포함 목록 길이 0–2, 재조회·실패·응답·재선택을 반복 | 89개와 161개 상태, 도달 검사 4개 통과, 변이 5개 검출 |

첫 모델은 사용자 동작을 세는 독립 번호로 실제 세대 검사를 대조한다. 앱을 열어도 위치 조회가 시작되지 않는 경우, 외부 링크만 제공하는 정류장에 실시간 요청을 보내는 경우, 직전 정류장의 도착 시간을 계속 표시하는 경우를 각각 변이로 검사했다. 두 번째 모델은 첫 모델에서 허용된 현재 응답에 대해 사용자가 선택한 차량과 표시된 항목을 대조한다. 위치·정류장 목록 등 비동기 작업은 이벤트 루프에서 한 번에 하나씩 재개된다고 가정한다. 실제로 같은 정류장 데이터 Promise를 공유하는 요청도 모델에서는 완료 순서를 자유롭게 바꿀 수 있다. 거리 계산, GPS 오차, 기기별 권한 창과 외부 교통 데이터의 정확도는 이 모델의 검사 범위 밖이다.

기존 모델 기준선과 비교해 사용자가 요청한 자동 조회에 맞춰 초기 상태를 바꿨다. 초기 상태에는 현재 위치 요청 한 건이 대기한다. 기존 속성 5개는 보존하고 자동 시작과 외부 링크 전환 속성 2개를 추가했다. 기준선 지문은 `a1dc9b25888d`에서 `13574913c648`로 갱신했고, 새 기준선으로 재비교한 결과가 일치했다.

## 실제 브라우저 재현

Chrome 157.0.8103.79에 앱 HTML과 안성 정류장 데이터를 로드하고 GPS와 API 응답 시점을 제어했다. 검색 후 도착한 옛 위치 및 목록 응답, 정류장을 바꾼 후의 옛 도착 정보, 같은 정류장에서 늦게 도착한 오류, 다른 정류장 ID를 포함한 현재 응답을 검사했다.

자동 조회를 추가한 `transit.js` Git blob `1f1e88541a40aa13ac3f9075b806ba943f3a4cf7`에서도 Chrome 157로 확인했다. 안성맞춤공감센터 좌표에서 별도 입력 없이 33182번 정류장이 선택됐다. 도착 응답을 보류한 채 인접한 시민회관(618)을 선택하고 이전 응답을 반환했을 때 정류장 이름과 지도 링크가 유지됐고, 추가 도착 요청이나 이전 차량 표시가 없었다.

Git blob `e6e44de8bb028442894bb65215d0f3abd65c99fd`에서는 T2를 고른 후 새로고침을 연속 두 번 누르고 새 목록 `[T3, T2]`를 먼저 받으면 선택이 T3으로 바뀌었다. 수정본에서는 T2가 유지됐다. 이후 T2가 없는 목록을 두 번 받으면 예약할 수 없고, 통신 실패 후 재시도해 T2가 돌아오면 다시 T2를 표시했다. 정류장을 바꾼 뒤에는 새 정류장의 첫 차량이 선택됐다. 모델에서 두 번째 새로고침이 저장한 차량 식별자를 지우게 바꿔도 `ChoicePreserved`가 위반됐다.

Git Bash에서 사용자 환경의 `env.sh`를 읽고 `FV`를 설치된 formal-verify 0.4.12 경로로 정한 뒤 프로젝트 루트에서 실행한다. 로컬 Windows 검증에서는 Git Bash/LF 호환 어댑터를 사용했다.

```bash
for model in TransitSelection TransitRide; do
  python3 "$FV/scripts/tlc.py" "$PWD/verification/tla/$model.matrix"
  python3 "$FV/scripts/mutate.py" "$PWD/verification/tla/$model.mutations"
done
node verification/test-transit-race.cjs
```

브라우저 재현에는 설치된 Chrome과 Playwright가 필요하다. Playwright를 프로젝트 외부에 둔 경우 `NAGAL_PLAYWRIGHT`에 모듈 경로를 지정한다.
