## 모델 검사

| 모델 | 검사 범위 | TLC 1.7.4 결과 |
| --- | --- | --- |

첫 모델은 사용자 동작을 세는 독립 번호로 실제 세대 검사를 대조한다. 두 번째 모델은 첫 모델에서 허용된 현재 응답에 대해 사용자가 선택한 차량과 표시된 항목을 대조한다. 위치·정류장 목록 등 비동기 작업은 이벤트 루프에서 한 번에 하나씩 재개된다고 가정한다. 실제로 같은 정류장 데이터 Promise를 공유하는 요청도 모델에서는 완료 순서를 자유롭게 바꿀 수 있다. 실시간 버스 데이터의 정확도, GPS 오차, 푸시 전달은 검사 범위 밖이다.

## 실제 브라우저 재현

Chrome 157.0.8103.79에 앱 HTML과 안성 정류장 데이터를 로드하고 GPS와 API 응답 시점을 제어했다. 검색 후 도착한 옛 위치 및 목록 응답, 정류장을 바꾼 후의 옛 도착 정보, 같은 정류장에서 늦게 도착한 오류, 다른 정류장 ID를 포함한 현재 응답을 검사했다.

Git blob `e6e44de8bb028442894bb65215d0f3abd65c99fd`에서는 T2를 고른 후 새로고침을 연속 두 번 누르고 새 목록 `[T3, T2]`를 먼저 받으면 선택이 T3으로 바뀌었다. 수정본에서는 T2가 유지됐다. 이후 T2가 없는 목록을 두 번 받으면 예약할 수 없고, 통신 실패 후 재시도해 T2가 돌아오면 다시 T2를 표시했다. 정류장을 바꾼 뒤에는 새 정류장의 첫 차량이 선택됐다. 모델에서 두 번째 새로고침이 저장한 차량 식별자를 지우게 바꿔도 `ChoicePreserved`가 위반됐다.

Git Bash에서 사용자 환경의 `env.sh`를 읽고 `FV`를 설치된 formal-verify 0.4.12 경로로 정한 뒤 프로젝트 루트에서 실행한다. 로컬 Windows 검증에서는 Git Bash/LF 호환 어댑터를 사용했다.

```bash
for model in TransitSelection TransitRide; do
  python3 "$FV/scripts/tlc.py" "$PWD/verification/tla/$model.matrix"
  python3 "$FV/scripts/mutate.py" "$PWD/verification/tla/$model.mutations"
done
node verification/test-transit-race.cjs
```

브라우저 재현에는 설치된 Chrome과 Playwright가 필요하다. Playwright를 프로젝트 외부에 둔 경우 `NAGAL_PLAYWRIGHT`에 모듈 경로를 지정한다.
