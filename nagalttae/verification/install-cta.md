# 두 설치 버튼의 브라우저 설치 요청 검증

페이지 상단과 푸시 알림 영역의 버튼은 `app.js`의 `mountInstall`에서 같은 설치 이벤트를 사용한다. 두 버튼 중 하나가 브라우저 설치 창을 열면 응답을 기다리는 동안 양쪽 버튼이 비활성화된다. 사용자가 설치 창을 닫으면 두 버튼이 다시 활성화된다. 새 이벤트가 없을 때 다시 누르면 수동 설치 안내를 열고, 기다리는 사이 브라우저가 새 이벤트를 줬다면 그 이벤트로 다시 시도한다. 브라우저가 오류를 반환하면 설치 가능한 화면에서 즉시 안내를 연다.

| 점검 | 2026-11-25 결과 |
| --- | --- |
| 실제 Chrome에 지연 가능한 브라우저 설치 이벤트를 연결 | 두 버튼의 교차 사용, 진행 중 중복 클릭, 거절 뒤 새 이벤트 보존, 오류·수동 안내 구분, 설치 성공 시 두 버튼 숨김과 잠금 해제를 확인했다. |
| 설치 알림과 안내창이 겹치는 순서 | 수정 전에는 설치 완료 이벤트 뒤에 늦은 오류가 오면 안내창이 다시 열렸다. 수동 안내가 열린 상태에서 독립 실행 모드로 전환해도 안내창이 남았다. 같은 이벤트 순서를 수정 후 다시 실행해 두 경우 모두 버튼과 안내창이 숨겨지는 것을 확인했다. |
| TLC 모델 검사 | 브라우저 이벤트를 0개, 1개, 2개, 3개까지 허용해 각 범위에서 가능한 순서를 검사했다. 총 640개 상태에서 검사 4개와 도달 조건 6개를 통과했다. |
| 변이 검사 | 모델 복사본에 설치 완료 뒤 안내 표시, 이벤트 재사용·유실, 버튼 잠금 해제 누락 등을 넣어 오류 12개를 모두 검출했다. |

모델은 브라우저가 새로 보낸 이벤트의 식별자가 서로 다르고 자바스크립트 이벤트 핸들러는 `await` 전까지 동기적으로 실행된다고 가정한다. 브라우저가 설치 이벤트를 발급하거나 설치 창의 응답을 돌려주는 시점은 정하지 않는다. 실제 운영체제의 설치 창, 설치 자격 판정, 푸시 알림 권한은 검증 범위 밖이다.

모델과 실행 조건은 [InstallCTA.tla](tla/InstallCTA.tla), [InstallCTA.matrix](tla/InstallCTA.matrix), [InstallCTA.mutations](tla/InstallCTA.mutations)에 있다. 프로젝트 루트에서 `FV`를 설치된 formal-verify 스킬 경로로 지정한 뒤 실행한다.

```bash
bash "$FV/scripts/tlc-matrix.sh" "$PWD/verification/tla/InstallCTA.matrix"
python3 "$FV/scripts/mutate.py" "$PWD/verification/tla/InstallCTA.mutations"
```
