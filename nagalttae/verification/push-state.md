# 웹 푸시 예약과 발송 검증

서버는 푸시 구독의 엔드포인트와 키로 식별한 Durable Object에 활성 일정을 하나 저장한다. 같은 휴대전화라도 브라우저 프로필이나 구독 키가 달라지면 별개로 취급한다. 모델은 `push-server/schedule.js`의 `change`·`afterAttempt`와 `push-server/worker.js`의 `ReminderDevice`를 대상으로 한다. 모델 첫머리에 검사한 소스의 Git blob을 기록했다.

| 모델 | 검사한 동작 |
| --- | --- |
| `tla/PushRevision.*` | 교체·취소는 저장한 버전과 일치해야 한다. 아직 미래인 동일 일정의 재시도는 현재 남은 이벤트와 버전을 그대로 반환한다. 응답은 저장 커밋 후에만 가능하며, 같은 구독의 알람 처리와 수정은 겹치지 않는다. |
| `tla/PushDelivery.*` | 준비·출발 시각이 같으면 하나로 합치고, 이미 지난 준비 시각은 건너뛴다. 일시 오류 후 재시도할 때 다른 알림의 예정 시각을 보존한다. 404·410은 구독의 남은 이벤트를 정리한다. 키를 얻는 동안 유예 시간이 지나면 전송을 건너뛴다. |
| `tla/PushAudit.*` | 예약·취소 성공은 저장 뒤에 기록하고, 교체·취소·발송 결과에 해당 예약 ID와 예정 시각을 담는다. 발송 결과는 공급자 응답을 받은 뒤, 다음 대기열 상태를 저장하기 전에 기록한다. |

TLC 1.7.4에서 예약 모델은 4,473개 상태와 도달 검사 3개, 발송 모델은 8,408개 상태와 도달 검사 7개를 통과했다. 예약 변이 6개와 발송 변이 7개를 모두 검출했다. 종료 기록을 무시하는 변이는 이전과 같은 일정이 다시 생성되는 전용 속성에서 검출됐고, 키를 기다린 뒤 기한을 확인하지 않는 변이는 만료 발송 속성에서 검출됐다.

취소하거나 마지막 이벤트를 정리할 때 서버는 새 무작위 버전과 삭제 시각만 30일간 보관한다. 이 기간에 예전 최초 요청이 `expected: null`로 다시 도착하면 버전 충돌로 거절한다. 보관 기한이 끝났을 때 원래 접수할 수 있었던 출발 시각은 이미 지났다. 이 성질은 등록 가능한 일정 상한과 보관 기한이 모두 30일이고 벽시계가 앞으로 진행한다는 조건을 사용한다.

## 실제 코드와 경계값

`node verification/test-push-state.mjs`는 운영 모듈을 직접 불러온다. 이미 처리한 준비 이벤트가 있는 일정의 재전송, 현재 버전과 다른 수정·취소, 종료 후 예전 최초 요청, 30일 상한 바로 전과 정확한 상한, 시간이 같은 알림을 검사한다. 준비·출발 종류 2개, HTTP 상태 15개, 시각 9개를 조합한 실제 코드 270개 벡터로 15초 재시도 지연과 5분 만료 기한도 검사했다.

`push-server`에서 `node test-delivery.mjs`를 실행하면 로컬 workerd에서 예약부터 알람 처리까지 실행한다. 테스트 수신기가 실제 VAPID 헤더와 암호화된 준비·출발 패킷을 받아 두 페이로드를 복호화했고, 중복 예약과 취소 후 재요청을 확인했다. 외부 푸시 제공자와 실기기 알림 표시는 이 검사 범위 밖이다.

`PushAudit`는 한 구독과 두 예약 버전에서 494개 상태, 도달 검사 6개, 변이 7개를 검사했다. 공급자 결과와 로그 호출 시점을 모델링한다. Cloudflare 로그 수집·보관과 기기 수신은 외부 동작이다. `push-server`에서 `node test-audit.mjs`를 실행하면 실제 런타임의 로그 필드 13건과 구독 자격 정보가 포함되지 않는지 검사한다. 여기에는 예약 교체, 취소 충돌, 201 수락, 503 재시도, 410 구독 종료가 포함된다.

2026-11-25 배포 뒤 운영 Worker 버전 `dfc6fed9-d52c-43e1-a2d0-eb1ccbd6e8f3`에서 로그 저장 설정을 확인했다. 합성 구독으로 접수·취소·410 거절 로그를 확인했고, 별도 Chrome 프로필에서 준비·출발 알림을 실제로 받은 뒤 두 201 수락 로그를 같은 예약 ID와 대조했다. 이 환경의 Cloudflare 로그인으로는 보관 로그 API가 403을 반환했다. [Cloudflare Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/)

## 중복이 생길 수 있는 경우

푸시 서비스가 패킷을 받은 직후, 서버가 이벤트 삭제를 커밋하기 전에 중단되면 복구한 큐에 이벤트가 남는다. TLC는 같은 준비 또는 출발 푸시를 다시 보내는 경로에 도달했다. 응답 타임아웃 뒤에도 상대 서비스가 첫 요청을 수락했을 수 있다. 정상 발송 후 큐 저장을 마친 이벤트는 다시 예약하지 않는다. OS 표시 시각과 알림 수신은 푸시 제공자 및 기기 상태에 따른다.

모델은 구독 하나, 서로 다른 버전 최대 3개, 단조 증가하는 시각, 원자적인 저장 트랜잭션, 객체 단위의 이벤트 직렬화를 가정한다. 발송 모델에서 재시도 간격을 1칸, 유예 기간을 3칸으로 줄여 경계 순서를 검사했다. 실제 서비스 시간 단위는 위 JavaScript 검사에 적용했다.
